# Hypermarket Logistics AI

Асинхронный бэкенд-сервис на **FastAPI** для оптимизации и автоматизации процессов сборки e-commerce заказов в торговых залах розничных гипермаркетов. Проект реализует построение оптимальных маршрутов обхода торговых зон, динамический расчёт временных нормативов сборки и интеллектуальный предиктивный скоринг на основе машинного обучения.

## 🧠 Архитектура машинного обучения (Scikit-Learn + Pandas)

В системе реализован отказ от статических жестко зашитых правил в пользу Data-Driven прогнозирования операционных показателей. С целью оптимизации сетевых потоков и предотвращения блокировки Event Loop тяжелыми вычислительными операциями применён паттерн **Warm-up Cache**:

1. Инициализация пула подключений к БД и фоновое обучение моделей происходят однократно при старте приложения в асинхронном контексте `lifespan`.
2. Обучающая выборка генерируется автоматически, симулируя 10 000 исторических записей в СУБД **PostgreSQL** (драйвер `asyncpg`). Скоростная вставка данных реализована через бинарный протокол `copy_records_to_table`.
3. Веса обученных моделей кэшируются в оперативной памяти (`ML_MODELS_CACHE`).
4. Эндпоинты выполняют только мгновенное извлечение моделей из RAM и вызов метода `.predict()`, обеспечивая Low Latency отклик системы.

### Используемые модели

- **LinearRegression (Прогноз операционной нагрузки):** анализирует ретроспективные данные входящего потока заказов конкретной торговой точки в зависимости от комбинации параметров «час смены» и «день недели». На основе прогноза вычисляется динамический коэффициент `kpi_time_modifier` для корректировки временных нормативов сборки.
- **LogisticRegression (Предиктивная автозамена):** оценивает вероятность отсутствия товара-аналога на полке (`shelf_absence_probability`) в текущий час и день недели на основе исторической частоты отмен позиций сборщиками. Модуль снабжён жесткой валидацией выборки для каждого товара (минимум 5 исторических записей и обязательное присутствие двух классов — доставлен/отменен) для защиты алгоритма от падения на редких позициях.

## 🚀 Ключевые компоненты и бизнес-логика

- **Repository Pattern:** проект строго разделён на независимые архитектурные слои. Контроллеры в файле `main.py` отвечают исключительно за маршрутизацию и валидацию входящих Pydantic-схем, а вся логика взаимодействия с СУБД инкапсулирована в классы `OrderRepository` и `AnalyticsRepository`. Сырые SQL-вызовы в теле эндпоинтов отсутствуют.
- **Динамическая мульти-маршрутизация (Multi-picking):** система поддерживает сквозное объединение корзин нескольких клиентов в единый оптимальный маршрут сборки на основе реальных топологий крупных торговых сетей (Globus, Перекрёсток, Пятёрочка, Ашан, Магнит Семейный).
- **Алгоритм дифференцированного штрафа за вес:** выполняет парсинг весовых характеристик из наименований позиций с помощью регулярных выражений. Алгоритм игнорирует стандартную фабричную упаковку (ровно 1 кг), рассчитывая добавочное время на ручное взвешивание и фасовку исключительно для целевых весовых категорий («Овощи и фрукты», мясные отделы).
- **Учёт загруженности зон (Congestion):** система динамически отслеживает количество активных заказов в каждой зоне и корректирует время сборки через коэффициент загруженности (1.0 / 1.3 / 1.6).
- **Нечёткое сопоставление товаров:** модуль `find_zone_for_item` использует трёхуровневую стратегию (exact match → token subset → fuzzy с якорем) для распознавания товаров с разными названиями в разных магазинах.
- **Генерация операционной отчётности:** модуль на базе `openpyxl` формирует детализированные Excel-отчёты эффективности смены сотрудников (с возможностью фильтрации по конкретной торговой сети через query-параметры) с автоматическим выравниванием ячеек по максимальной длине данных и условным цветовым форматированием зон риска.

## 🛠 Технологический стек

- **Core:** Python 3.11+, FastAPI, Uvicorn, Pydantic v2 (Asyncio).
- **Data & Machine Learning:** Scikit-Learn, Pandas, NumPy.
- **Database:** PostgreSQL 15, асинхронный драйвер asyncpg (пулинг соединений).
- **Orchestration & Reporting:** Docker, Docker Compose, OpenPyXL.

## 📦 Порядок развёртывания и тестирования

Инфраструктура полностью оркестрирована с помощью Docker Compose. Бэкенд-сервис снабжён механизмом `healthcheck` и автоматически дожидается полной готовности СУБД перед запуском и прогревом кэша.

### 1. Клонирование и настройка окружения

```bash
git clone https://github.com/Haidari08/hypermarket-logistics-ai.git
cd hypermarket-logistics-ai
cp .env.example .env
```

### 2. Запуск всей инфраструктуры

```bash
docker compose up --build
```

### 3. Запуск автоматических интеграционных тестов (в соседнем окне терминала)

```bash
python test_api.py
```

Скрипт случайным образом выбирает одну из доступных в `config.py` торговых сетей и проверяет корректность ответов всех ключевых эндпоинтов сервиса, включая валидацию структуры JSON и скачивание изолированного Excel-файла аналитики. Всего **25 проверок**.

### 4. Интерактивная документация

Swagger Open API доступен по адресу: **http://localhost:8001/docs**

## 📋 Основные эндпоинты

| Метод | Путь | Назначение |
|-------|------|-----------|

## 🗂 Структура проекта

```
.
├── main.py                 # FastAPI-приложение, эндпоинты, хендлеры исключений
├── config.py               # Каталог товаров, топологии магазинов, зоны
├── database.py             # Пул подключений, схема БД, генерация сида
├── repositories.py         # Repository Pattern: SQL-запросы
├── ml_engine.py            # Обучение и кэш ML-моделей
├── schemas.py              # Pydantic-схемы запросов
├── safari_response.py      # JSONResponse с charset=utf-8 для Safari
├── test_api.py             # Интеграционные тесты (25 проверок)
├── requirements.txt        # Python-зависимости
├── docker-compose.yml      # Оркестрация: PostgreSQL + FastAPI
├── Dockerfile              # Образ Python 3.11-slim
└── .env.example            # Шаблон переменных окружения
```

## 🔐 Конфигурация

Все секреты хранятся в `.env` файле (не коммитится в git). Шаблон — `.env.example`:

## 📊 Пример работы

```bash
curl -X POST http://localhost:8001/api/v1/orders/build-optimized-route \
  -H "Content-Type: application/json" \
  -d '{
    "store_id": "globus",
    "items": ["Молоко 3.2%", "Хлеб Бородинский", "Бананы Эквадор", "Куриное филе 1кг"]
  }'
```

Ответ содержит оптимальный маршрут обхода зон с учётом загруженности, веса товаров и пикового времени:

```json
{
  "status": "success",
  "store_id": "globus",
  "total_unique_zones_to_visit": 4,
  "estimated_total_picking_time_minutes": 8.2,
  "optimized_route_steps": [...]
}
```
